# 每日工时

安卓优先的本地工时应用，代码也兼容 iOS。直接录入小时数，不包含上下班打卡或夜班功能。

## 版本管理

源码使用 Git 管理，私人仓库为 https://github.com/xiaojujuovo/daily-work-hours ，主分支为 `main`，当前版本标签为 `v1.5.0`。后续更新通过提交和版本标签保存。

仓库包含源码、依赖锁文件、测试、使用说明及截图；安装包、历史 ZIP 归档、编译工具、缓存和签名密钥保留在本地。克隆后先执行 `npm.cmd ci` 安装依赖。为已有安装版生成覆盖更新时，须使用本地原有 `.signing/` 签名，请单独妥善备份。

## 功能

- 每天一条记录，支持补记、修改、删除及备注；小时数支持两位小数，范围 0–24。
- 设置每周哪些日期是工作日、正常工时门槛。工作日前门槛内正常，超过部分默认1.5倍，可指定工作日超出部分按2倍，其余日期全部2倍，3倍手动填写。
- 正常、1.5倍、2倍、3倍均可修改；修改分类自动调平，优先扣正常工时，再依次扣其它倍率，减少倍率则补回正常工时。分类合计必须等于总工时。修改总工时会重新分配，可点击重新分配重置手动值。
- 加班工资按1.5、2、3倍工时和时薪计算；正常工时不自动折算工资。自定义工资条收入/扣款，支持默认组成同步所有月份及单月自定义；整月可批量更新时薪与工资开关。
- 月历网格显示每天工时：超过8小时红色“加”、8小时绿色“正”、大于0不足8小时黄色“早”；保存0小时自动显示蓝色休息格和“休”，未记录显示横线。点击日期可直接补记或修改。保留月度合计，导出本月或全部 CSV 表格，可使用 Excel 打开（不是 .xlsx 文件）。
- JSON完整备份及恢复；恢复前校验，并要求确认替换。建议先备份当前数据。
- 本地通知，默认时间18:00；启用时请求权限，可选择提醒星期。已保存日期不安排通知，通知打开对应日期。增量更新通知队列并保留当天延迟通知；提供通知频道和精确闹钟权限状态、下次提醒时间、立即测试与1分钟测试，以及系统权限设置入口。
- 不需要账号，不连接业务服务器；手机数据保存在应用本地，卸载后清除。Android 系统云备份已禁用。

## 运行和安装

1.4.0新增月度调休（按1.5→2→3倍抵扣）及分类日记录明细弹窗，工资和CSV使用调休后工时，完整备份保留各月调休。1.3.1代码、安装包和说明已归档于 `archives/daily-work-hours-1.3.1-20261006.zip`。

1.5.0增加工作日2倍加班、工资条组成、月度更多设置和关于页面。更新前1.4.0已归档为archives/daily-work-hours-1.4.0-20261011.zip。

日常使用参阅 [使用说明.md](使用说明.md)。新版安装包保存在 `release/daily-work-hours-1.5.0.apk`。已有旧版的手机直接覆盖更新，不要先卸载。

已安装依赖时：

```powershell
npm.cmd test
npm.cmd run check
npm.cmd start
```

开发预览可使用与 Expo SDK 57 匹配的 Expo Go。通知功能需要在实际安卓安装版中验证。电脑预览：`npm.cmd run web`，不支持手机系统通知。

生成安卓 APK 需要 JDK17、Android SDK和构建工具：

```powershell
npx.cmd expo prebuild --platform android
npx.cmd expo run:android --variant release
```

正式发布需设置自己的签名密钥。也可使用 Expo EAS：登录自己的 Expo 账号后，运行 `npx.cmd eas-cli build --platform android --profile preview`。EAS 会上传构建源代码到 Expo 服务，不会上传手机里的工时数据。

本项目的本地构建脚本会生成专用签名，保存在已忽略的 `.signing/` 文件夹。请保留该文件夹，用同一签名覆盖安装更新才能保留手机记录，不要将签名文件分享或提交到代码仓库。已准备好项目内工具时，可运行：

```powershell
.\scripts\build-in-temp.ps1
```

本次构建已获用户明确同意接受 Android SDK 许可。便携构建工具位于 `.tools/`，Gradle缓存位于 `.gradle-local/`。Windows 中文项目目录会使用系统临时目录中的英文路径完成构建，APK 自动复制回 `release/`。

iOS源码兼容，安装签名需要 Apple 开发者账号及相应构建环境，尚未验证实机。

## 提醒的实际限制

每次启动或回到应用、保存记录、保存设置时，重新安排未来60天的本地通知；最多60条，以兼顾 iOS 的待发送通知数量限制。请至少每月打开应用一次，60天不打开后通知会停止，下一次打开重新安排。设置修改需要点击保存。

通知权限或手机省电策略可能影响提醒，软件不会自动保证系统权限。没有申请精确闹钟权限，因此不承诺精确到分钟。当前使用本地单次通知，已记录日期取消通知，无远程推送。

历史记录以保存时的倍率为准，实际工资核算以单位规则为准。
